# 테스트 파일과 실제 앱 구동의 관계

## 핵심 요약

**테스트 파일들은 실제 앱 구동에 전혀 영향을 주지 않습니다!**

- ✅ 테스트 파일들은 `test/` 폴더에 있습니다
- ✅ 실제 앱 코드는 `lib/` 폴더에 있습니다
- ✅ Flutter는 자동으로 `test/` 폴더를 제외하고 앱을 빌드합니다

## 상세 설명

### 1. 파일 구조 분리

```
capstone/
├── lib/              ← 실제 앱 코드 (앱 빌드 시 포함됨)
│   ├── main.dart     ← 앱이 여기서 시작
│   ├── pages/
│   └── services/
│
└── test/             ← 테스트 코드 (앱 빌드 시 제외됨)
    ├── unit/         ← 유닛 테스트
    └── widget/       ← 위젯 테스트
```

### 2. 앱 빌드 시 어떤 일이 일어나는가?

#### ✅ 실제 앱 실행 (`flutter run` 또는 `flutter build`)
```
1. Flutter가 lib/ 폴더만 읽습니다
2. test/ 폴더는 완전히 무시됩니다
3. 앱이 lib/main.dart부터 시작됩니다
4. 테스트 파일은 전혀 포함되지 않습니다
```

#### ✅ 테스트 실행 (`flutter test`)
```
1. Flutter가 test/ 폴더만 읽습니다
2. lib/ 폴더의 코드를 가져와서 테스트합니다
3. 앱은 실행되지 않습니다
4. 테스트 결과만 출력됩니다
```

### 3. 실제 확인 방법

#### 앱 실행 (테스트 파일 무시됨)
```bash
flutter run
# → lib/main.dart만 실행, test/ 폴더는 완전히 무시됨
```

#### 테스트 실행 (앱 실행 안 됨)
```bash
flutter test
# → test/ 폴더의 테스트만 실행, 실제 앱은 실행 안 됨
```

### 4. 왜 이런 구조인가?

Flutter는 표준적으로:
- `lib/` = 실제 앱 코드 (프로덕션 코드)
- `test/` = 테스트 코드 (개발용)
- `integration_test/` = 통합 테스트 (선택사항)

이렇게 분리하여:
- 📦 앱 크기를 작게 유지 (테스트 코드 제외)
- 🚀 빌드 속도 향상
- 🔒 테스트 코드가 앱에 포함되는 실수 방지

### 5. 테스트 파일이 하는 일

#### 테스트 파일의 역할:
```
test/unit/services/auth_api_test.dart
├── AuthApi 클래스를 테스트함
├── 실제 앱 코드(lib/services/auth_api.dart)를 가져와서 사용
└── 테스트만 실행하고 끝남 (앱 실행 안 함)
```

#### 실제 앱 코드는 변경 안 됨:
```
lib/services/auth_api.dart
├── 실제 앱에서 사용하는 코드
├── 테스트 파일과는 별개
└── 앱 실행 시 이 코드만 사용됨
```

### 6. 빌드 결과물 확인

앱을 빌드하면:
- APK/AAB 파일에 `lib/` 폴더 내용만 포함
- `test/` 폴더는 빌드 결과물에 전혀 포함되지 않음
- 테스트 코드는 최종 앱 크기에 영향 없음

### 7. 예시로 이해하기

#### 시나리오 1: 앱 실행
```bash
flutter run
```
**실행되는 코드:**
```
lib/main.dart → DeliveryApp() 실행
lib/pages/login.dart → LoginPage 표시
lib/services/auth_api.dart → AuthApi.login() 사용
```

**실행되지 않는 코드:**
```
test/unit/services/auth_api_test.dart → 무시됨
test/widget/login_page_test.dart → 무시됨
```

#### 시나리오 2: 테스트 실행
```bash
flutter test
```
**실행되는 코드:**
```
test/unit/services/auth_api_test.dart → AuthApi 테스트
test/widget/login_page_test.dart → LoginPage 테스트
```

**실행되지 않는 것:**
```
실제 앱 UI → 표시 안 됨
실제 앱 기능 → 실행 안 됨
```

### 8. 결론

| 항목 | 실제 앱 구동 | 테스트 실행 |
|------|------------|------------|
| **실행 코드** | `lib/` 폴더만 | `test/` 폴더만 |
| **앱 UI 표시** | ✅ 표시됨 | ❌ 표시 안 됨 |
| **빌드 포함** | ✅ 포함됨 | ❌ 제외됨 |
| **최종 앱 크기** | ✅ 영향 있음 | ❌ 영향 없음 |
| **사용자 경험** | ✅ 실제 앱 사용 | ❌ 개발자용 |

### 9. 요약

**테스트 파일은:**
- ✅ 코드 품질을 확인하는 도구
- ✅ 버그를 찾는 도구
- ✅ 리팩토링 시 안전장치
- ❌ 실제 앱 실행에 포함되지 않음
- ❌ 앱 성능에 영향 없음
- ❌ 사용자가 볼 수 없음

**마치:**
- 실제 음식 (`lib/`) = 고객이 먹는 것
- 레시피 테스트 (`test/`) = 요리사가 연습하는 것

레시피 테스트는 음식 맛을 개선하기 위한 것이지, 실제 음식에는 포함되지 않습니다!
